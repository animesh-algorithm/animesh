# Architecture

Independent Next.js App Router app, React Server Components, small client boundaries for clipboard and GIF playback. The official @notionhq/client SDK runs only on the server. All network reads use no-store SDK requests. Four bounded attempts handle 429 and transient 5xx errors; retry-after is capped at five seconds. All page/block pagination is followed and nested children retrieved sequentially to avoid request bursts. Failed/partial archives throw a sanitized exception, never cache an empty success.

A single public archive snapshot (validated metadata and recursive blocks) uses Next's persistent unstable_cache with revalidate=300. Pages/routes are dynamic, so there is no separate full-route cache prolonging publication changes. Only published entries enter the snapshot. The first traffic after expiry can see the previous snapshot while Next refreshes it. This is a traffic-driven refresh window, not a scheduled guarantee; upstream failures may retain the previous successful public snapshot. Preview reads never use this cache. SDK logs are disabled to avoid leaking provider output.

Routes: /, /[slug], /tags/[tag], /rss.xml, /sitemap.xml, /robots.txt, /preview, /preview/[pageId], /api/auth/[...nextauth], /media/[pageId]/[blockId]. Search uses q and tag query parameters, with tag paths providing canonical archives. Unknown tags/slugs return 404. Search pages are noindex. RSS is escaped XML; article JSON-LD escapes less-than characters; content rendering uses React text nodes and safe link protocols. Code highlighting uses Shiki tokens, never CMS HTML. Embeds render safe links, never iframes.

Auth.js Google OAuth uses an encrypted/signed JWT session, an app-specific host-only cookie, verified Google email and an exact BLOG_OWNER_EMAIL comparison. There is no database adapter. Owner access is rechecked in each preview page and draft-media route before any content reads; a layout check alone is insufficient. OAuth sessions expire after eight hours. Preview is dynamic, private/no-store, noindex/nofollow. No credential or session is shared with admin.

Media markup contains only page/block identifiers. The route verifies public archive membership and freshly retrieves the page to confirm publication and source membership. Draft media requires owner authorization. Block IDs must exist in that page's recursively fetched image tree. Thumbnail reads freshly retrieve the page files property. File objects are refreshed on every request, near-expiry retried, and failed signed downloads retried once with a newly retrieved file. Bytes use private/no-store responses, so unpublishing does not leave a CDN image cache. Public image responses permit indexing; preview images stay noindex. Static images are resized to at most 1600px and delivered as WebP when smaller; GIF playback and first-frame PNG controls are preserved. Images have exact HTTPS hostname allowlists, checked redirects, timeouts, a 20MB cap, safe image MIME types and bounded decoded pixels for first-frame generation. Arbitrary CMS URLs cannot turn this into an unrestricted proxy.

Deploy with Vercel root apps/blog, Node 24, pinned pnpm workspace install, next build. The app-local Turbo env list includes server configuration without sharing it. Vercel preview provisioning is separate from production launch.
