# Architecture
Admin owns versioned Supabase PostgreSQL migrations. Link UUIDs are immutable; slugs are case-sensitive, immutable and reserved forever. Link edits affect the next uncached lookup. Soft deletion preserves history.
Supabase SSR cookies carry sessions. Server calls getUser to verify identity and checks private owner UUID, email and Google identity. Missing configuration denies access. Proxy refreshes cookies. Every database adapter repeats owner verification. No service-role key is used. RLS checks a private database owner record and verified Google JWT. All mutation endpoints require the configured exact Origin, JSON content type and bounded request bodies. OAuth uses PKCE and a fixed callback; no user-controlled redirect target.
Owner-only SQL RPCs perform directory queries, complete CSV exports and PostgreSQL aggregations. There are no shared packages. Native links are created by the app; migrated metadata is preserved but import tooling is deferred.
Analytics use UTC timestamps and Asia/Kolkata buckets. Ranges end at one captured instant; finite ranges compare the immediately preceding equal duration. Unique visitors are distinct non-null stable HMAC hashes per link, an estimate. Bots remain in totals. Events have no expiration. All-time has no prior comparison. Heatmap cells count clicks by weekday/hour in India time; UTC timestamps retain precise instants.
Links invokes two security-definer functions under links_runtime: resolve_link and record_click. It has no table privileges. Idempotent event UUID insertion and lifetime count updates happen in one transaction. after() recording is best effort, including when shutdown/network errors occur; lifetime counts reflect recorded events, not guaranteed delivered responses.
