# Implementation validation

Validated locally on 2026-09-17 with Node 24.21.0 and pnpm 10.34.5.

- Filtered Admin lint, typecheck, test and production build checks passed. Equivalent root Turbo lint/test/build/typecheck checks passed for all four apps. Total: 69 tests (Admin 24, Links 9, Portfolio 22, Hire 14).
- SVG title regression tests cover zero-click trends, grouped bucket sums and map labels. `pnpm --filter animesh-admin exec tsx scripts/charts-hydration-qa.tsx` hydrates actual server-rendered charts in Chromium at 375/768/1024/1440 with no recoverable hydration errors. Set `QA_CHROME_EXECUTABLE` to use a locally installed Chrome, as with the main browser QA script.
- The actual migration ran in PGlite PostgreSQL with Supabase-compatible auth claims/roles. Fixtures contain 1,202 links and 1,109 events before mutation probes. Checks cover missing owner configuration, non-owner/non-Google denial, table/function privilege boundaries, case-sensitive nested slugs, immutable fields, deletion history, 1,000+ row exports, pagination, exact period boundaries, India buckets, repeated/missing hashes, bot totals and atomic/idempotent event writes including rollback on invalid metadata. This is local PostgreSQL verification, not a hosted Supabase verification.
- Links route tests cover fresh lookup on edits/deletion, query merging/duplicate values/fragments, uncached 302/404/410/503 statuses, HEAD without writes and sanitized analytics-write failures. Admin tests cover expired sessions, direct private APIs, missing configuration, rejected Google accounts, exact mutation origins, bounded JSON bodies, slug collisions/validation, formula-safe CSV and real PNG QR output.
- Browser QA passed 56 views: login, directory, directory empty state, error state, four analytics tabs and analytics empty state at 375/768/1024/1440, plus real home pages on ports 3000/3001/3002/3003 at those widths. It checks create/delete dialog initial focus, Escape dismissal and focus restoration; mobile filter disclosure; copy status; 200% text enlargement; document/body/chart bounds; keyboard focus; reduced motion; image assets; and console/page errors. The dashboard uses a separate temporary loopback-only source-component fixture; no authentication bypass is present in the deployed apps. Screenshots and checks are emitted under the OS temp directory by qa:browser.
- Baseline exceptions: Portfolio and Hire lack /favicon.ico (404). These pre-existing assets were left unchanged and reported by QA. Portfolio also had duplicate disposable .next/types/* 2.ts artifacts; removing those resolved its initial typecheck failure. Tracked generated files were restored after checks.
- Production smoke probes on temporary ports 3102/3103 confirmed fail-closed Admin pages/APIs, private no-store headers, sanitized unavailable responses, and uncached Links lookup failures/HEAD behavior. Production output preserves Portfolio's dynamic / and Ask/API routes and Hire's prerendered / and inquiry route. New icons and robots routes are app-local; their paths are reserved from link creation.
- Frozen-lockfile installation passed. A parsed comparison verifies every original importer, package and snapshot remains unchanged; the lockfile only adds the new application dependency graph. Portfolio/Hire product source, configurations and package manifests were not changed. No shared package was created.

Not performed: hosted Supabase provisioning, Google OAuth sign-in against a real project, hosted privilege probes, live preview click recording, production deployments or DNS changes. Follow deployment.md with isolated preview data before the separate production launch. No credentials or production owner values were added.

QR preview addition (2026-09-17): Admin filtered lint/typecheck/24 tests/build and equivalent filtered root Turbo checks passed. Browser QA passed 56 views with directory/detail QR previews at all four widths, real PNG rendering from the isolated fixture, download endpoint wiring, keyboard opening, focus containment, Escape dismissal and trigger focus restoration. PNG requests remain on the existing authenticated route; live owner-session rendering was not exercised.
